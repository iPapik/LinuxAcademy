# LinuxAcademy — внутренняя платформа практического изучения Linux

Готовый исходный проект веб-платформы с учебными материалами на русском языке, тестами, интерактивной оболочкой Linux и автоматической проверкой практики. Установка на **собственную выделенную Linux VM**: портал работает за nginx/HTTPS; для каждого ученика Podman в rootless-режиме запускает отдельное учебное окружение.

## Быстрая установка через GitHub

На отдельной VM c Ubuntu Server 24.04 LTS или Debian 13:

```bash
sudo apt update
sudo apt install -y git ca-certificates
git clone https://github.com/iPapik/LinuxAcademy.git
cd LinuxAcademy
sudo bash scripts/install.sh
```

Установщик предложит создать первого администратора и настроит HTTPS, nginx, Python и rootless Podman. После успешной установки: `https://IP-сервера/`.

Полная инструкция по установке **через Git, обновлению и диагностике**: [INSTALL_GIT.md](INSTALL_GIT.md). Архивный способ установки также описан ниже.

## Что включено

- 11 модулей, 47 уроков (с разбором механик и команд), 49 проверяемых заданий, 94 тестовых вопроса с объяснениями.
- Дополнительный **справочник Linux-администратора из 23 разделов** прямо внутри сайта, без внешних ссылок и CDN. Практика распределена между Ubuntu, Debian и AlmaLinux.
- Три подготовленных при установке контейнерных образа: **Ubuntu 24.04 LTS**, **Debian 13**, **AlmaLinux 9**.
- Браузерный интерактивный терминал; полноценная shell-сессия сохраняет текущую директорию, поддерживает Ctrl+C, интерактивные команды, редакторы и историю.
- Подготовка исходных данных заданий и проверка реальных файлов, содержимого, прав, учётных записей и команд в лаборатории.
- Пользователи и администраторы, пароль от 12 символов, хеширование scrypt, сессии HttpOnly, CSRF, разграничение результатов.
- Статистика, прогресс, доступ с компьютеров локальной сети, HTTPS (первоначальный сертификат самоподписанный).
- Сайт и шрифты/терминал локальны и после установки не требуют внешних CDN.

**Ограничение:** три «машины» во встроенном браузерном терминале — это **контейнеры с Linux user space, не самостоятельные виртуальные машины**. В них нельзя полноценно отрабатывать загрузку ядра, GRUB, изменение реальных дисков, systemd как PID 1, сеть предприятия или настройку реального SSH-сервера. Эти темы помечены в уроках; для них включена отдельная инструкция **VIRTUAL_MACHINES.md**, предлагающая полнофункциональные VM-практикумы. Автоматическое создание VM через Hyper-V/VMware в версии 1.0 отсутствует.

## 1. Сервер и безопасность

Рекомендуется отдельная VM, **не DC, не файловый сервер, не боевой Zabbix/WSUS**:

- Хостовая ОС: чистая Ubuntu Server 24.04 LTS либо Debian 13 (64-bit).
- Минимум для небольшого стенда: 4 vCPU, 8 ГБ ОЗУ, 40 ГБ диска. Для десятков одновременных пользователей увеличьте RAM/CPU/диск, проверьте квоты Podman.
- SSH-доступ администратора с sudo, работающий DNS; для *первого развёртывания* требуется доступ к пакетным репозиториям ОС, PyPI, Docker Hub и Quay.io или настроенные корпоративные зеркала.
- Сеть: только HTTPS 443 от разрешённых рабочих мест. Разместите сервер в отдельной учебной VLAN, без прямого доступа к критическим сетям и гипервизорам.
- Установщик настраивает **rootless Podman** под выделенным аккаунтом `linuxacademy`. Контейнеры работают с `--network=none`, без `--privileged` и без монтирования каталогов хоста; по 1 vCPU, 768 МБ памяти, максимум 128 процессов на лабораторию. Rootless + namespaces снижают риск, но не гарантируют полной изоляции злонамеренного кода. Если ученики потенциально недоверенные, нужен отдельный гипервизор/хост с жёсткой сетевой изоляцией.

## 2. Установка с нуля

Подключитесь по SSH к подготовленной Linux VM, перенесите архив `LinuxAcademy.zip` и выполните:

```bash
sudo apt-get update
sudo apt-get install -y unzip
unzip LinuxAcademy.zip
cd LinuxAcademy
sudo bash scripts/install.sh
```

Скрипт последовательно устанавливает nginx, Python и rootless Podman; копирует приложение в `/opt/linuxacademy`, создаёт каталог базы `/var/lib/linuxacademy/data`, устанавливает Python-зависимости, **собирает три образа** (во время сборки загружает Linux-пакеты), создаёт TLS-сертификат, предлагает задать пароль первого администратора и запускает системные службы. По завершении отображает URL `https://IP-адрес/`.

Внимание: первичная сборка образов **не мгновенная** и зависит от корпоративных зеркал/интернета. Архив исходного проекта **не содержит** многогигабайтных OCI-образов — они автоматически собираются при установке. Если интернет запрещён, сначала нужны локальные зеркала или импорт заранее собранных OCI-образов в rootless-хранилище аккаунта `linuxacademy`.

### HTTPS и корпоративный сертификат

Первоначально nginx использует самоподписанный сертификат в `/etc/linuxacademy/tls/`. Браузер справедливо предупреждает о недоверенном удостоверяющем центре. Для реального внедрения замените сертификат/ключ на сертификат, выданный доверенным корпоративным CA, или измените пути `ssl_certificate`/`ssl_certificate_key` в `/etc/nginx/sites-available/linuxacademy`, затем:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Внутреннее имя (`academy.company.local`, например) задаётся **в вашем DNS** и должно совпадать с SAN сертификата. Установщик не настраивает вашу DNS-зону и не пытается интегрироваться с AD.

## 3. Первый вход и управление сотрудниками

1. Откройте `https://IP-сервера/` с рабочего компьютера в разрешённой сети.
2. Войдите с логином и паролем, заданными установщиком.
3. В панели **Пользователи** создайте отдельный аккаунт сотрудника, временный пароль от 12 символов.
   Отдельный раздел **Справочник администратора** содержит 23 главы с пошаговыми инструкциями, примерами и диагностикой.
4. Пользователь открывает урок, нажимает **Подготовить задание**, затем **Открыть терминал** и **Проверить результат**. Проверка использует состояние только его лаборатории.
5. После теста и выполнения всех заданий урок отмечается завершённым.
6. В разделе **Терминал Linux** можно выбрать ОС и начать свободную практику или сбросить окружение. **Сброс удаляет файлы лаборатории**, но не результаты уже выполненных проверок в профиле.

Создание второго администратора из консоли:

```bash
sudo -u linuxacademy env ACADEMY_DATA_DIR=/var/lib/linuxacademy/data \
  /opt/linuxacademy/.venv/bin/python /opt/linuxacademy/manage.py create-admin secondadmin
```

Смена пароля администратора через консоль:

```bash
cd /opt/linuxacademy
sudo -u linuxacademy env ACADEMY_DATA_DIR=/var/lib/linuxacademy/data \
  /opt/linuxacademy/.venv/bin/python manage.py reset-password admin
```

## 4. Проверка сервера и диагностика

```bash
sudo systemctl status linuxacademy nginx --no-pager
curl -k https://127.0.0.1/healthz
sudo journalctl -u linuxacademy -n 100 --no-pager
sudo bash /opt/linuxacademy/scripts/diagnose.sh
```

Список OCI-образов в **rootless** хранилище (не используйте `sudo podman images`, там другое хранилище):

```bash
LAB_UID=$(id -u linuxacademy)
sudo -u linuxacademy env HOME=/var/lib/linuxacademy \
  XDG_RUNTIME_DIR=/run/user/$LAB_UID podman images
```

Если rootless Podman отказывает в доступе: проверьте `grep '^linuxacademy:' /etc/subuid /etc/subgid`, `loginctl user-status linuxacademy`, наличие `/run/user/UID`, журнал systemd и ошибки `podman info`. На Ubuntu 24.04 следите за профилями AppArmor для user namespaces. **Не отключайте AppArmor и не переключайте Podman на root** просто ради обхода ошибки.

Если ошибка подключения терминала: проверьте, что приложение слушает `127.0.0.1:8086`, nginx проксирует WebSocket Upgrade, сертификат доверен браузеру и URL открыт по HTTPS. Во вкладке браузера посмотрите WebSocket `/ws/ubuntu`, HTTP 403 и консоль разработчика.

## 5. Резервное копирование и обновление

```bash
sudo bash /opt/linuxacademy/scripts/backup.sh
# Получится /var/backups/linuxacademy/academy-YYYY-MM-DD-HHMMSS.sqlite3
```

Резервируется **только база пользователей, тестов и прогресса**, консистентно через SQLite backup API. Для полной копии пользовательских учебных контейнеров используйте отдельную политику резервирования rootless Podman; на практике лаборатории удобнее делать одноразовыми.

Для обновления приложения: сохраните резервную копию, распакуйте **новую** версию в отдельный каталог и повторите `sudo bash scripts/install.sh`. Скрипт не удаляет БД, пересобирает учебные образы. При изменении моделей базы потребуется отдельная миграция: текущая 1.0 не реализует автоматические миграции схемы.

## 6. Как добавлять уроки и задания

Редактируемый источник: `content/build_curriculum.py`. Он формирует `content/curriculum.json` с текстом в Markdown, тестами и правилами проверки:

```bash
cd /opt/linuxacademy
python3 content/build_curriculum.py
sudo systemctl restart linuxacademy
```

**Важно:** проверочные `script` исполняются в контейнере. Меняйте учебный контент только доверенным администратором и проводите ревью сценариев. Для новых тем следует писать реальную теорию, уникальные критерии проверки и проверять их на всех заявленных дистрибутивах. Проект специально оставлен расширяемым, но не является автоматически обновляющейся энциклопедией всех существующих дистрибутивов Linux.

## 7. Каталоги, сервисы и порты

| Компонент | Значение |
|---|---|
| Код платформы | `/opt/linuxacademy` |
| SQLite с результатами | `/var/lib/linuxacademy/data/academy.sqlite3` |
| Systemd-сервис | `linuxacademy.service` |
| Nginx TLS | `/etc/nginx/sites-available/linuxacademy`, порт 443 |
| Python | uvicorn, `127.0.0.1:8086` (локальный доступ) |
| Контейнерный раннер | rootless Podman, пользователь `linuxacademy` |
| Учебный каталог внутри каждой лаборатории | `/workspace` |
| Сертификат | `/etc/linuxacademy/tls/server.crt` |

## 8. Проверка перед внедрением

Прежде чем открывать доступ всему предприятию, проверьте в отдельной VLAN: создание двух пользователей, изоляцию их файлов, выполнение и сброс задания, оценку теста, переподключение терминала, корректность HTTPS и бэкап/восстановление SQLite. Это локальный учебный продукт версии 1.0, не прошедший внешнюю проверку на проникновение и нагрузочное тестирование. Продуктивное предприятие требует настройки сегментации, контроля доступа, журналирования событий и процедуры обновления зависимостей.

Подробная практика на **полных виртуальных машинах** — в `VIRTUAL_MACHINES.md`.
